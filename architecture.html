#1 컴퓨터 기본 구조와 명령어 실행

1 — 컴퓨터 기본 구조

컴퓨터가 이해하는 정보는 데이터와 명령어 둘뿐이다. 핵심 부품은 넷이고, 이들을 잇는 통로가 메인보드의 시스템 버스다.

  • CPU — ALU(연산) · Register(data·명령어 저장) · 제어장치(명령어 해석 · 제어신호)
  • 메모리(RAM) — 현재 실행되는 프로그램의 명령어와 data
  • 보조기억장치 — SD · USB · SSD · HDD
  • 입출력장치 — 키보드 · 마우스 · 모니터
  • 메인보드 · 시스템 버스 — 부품끼리 정보를 주고받는 통로. 핵심 부품들을 연결하는 척추 같다

캐시 메모리는 Register 다음으로 CPU 에 가까운 메모리다. RAM 은 전원이 끊기면 날아간다.

메모리 — 번지마다 명령어 또는 data 가 들어 있다

메모리는 칸마다 번호(번지)가 붙은 사물함이다. CPU 는 “3번지를 가져와” 처럼 번지로만 지목한다.

핵심 — 명령어와 data 가 같은 메모리에 섞여 있다

1·2번지는 명령어, 3·4번지는 data 인데 생김새로는 구분이 안 된다. 둘 다 그냥 0 과 1 이다.

“1번지부터 명령어로 읽어라” 라고 CPU 가 정해줘야 비로소 갈린다. 이렇게 명령어와 data 를 한 메모리에 같이 두는 구조를 폰 노이만 구조라 한다.

  • 번지는 칸의 위치일 뿐 내용이 아니다. 그래서 오퍼랜드에 값 대신 번지를 적을 수 있다.
  • 5·6번지처럼 빈 칸도 있다. 프로그램이 올라오면 여기에 적재된다.
  • 전원이 끊기면 전부 날아간다. 그래서 보조기억장치가 따로 필요하다.

x86 이 뜻하는 것

흔한 오해

"레지스터가 32개" 라는 뜻이 아니다.

실제 뜻

레지스터 하나의 크기가 일반적으로 32bit 라는 뜻이다.

  • CPU 가 메모리를 읽거나 쓸 때 한 번에 32비트씩 전송한다. 한 번의 읽기/쓰기로 4바이트를 처리한다.
  • 32비트 주소를 쓰므로 2^32(약 42억) 개의 서로 다른 주소를 가리킬 수 있다. 즉 4GB(4,294,967,296 바이트) 범위까지만 주소 지정이 된다.
  • 그래서 8GB · 16GB 메모리는 못 쓴다. 커버가 안 된다.

레지스터 종류는 정말 많다 — GPR, segment, index & pointer, flag, 명령어 / 제어 / 디버그 / 테스트 / FPU / SIMD / Mask / MMX / 시스템 …

워드(word)

데이터 버스 관련 용어로, CPU 가 한 번에 처리할 수 있는 데이터 크기. 32bit, 64bit 등.

제어신호

컴퓨터 부품들을 관리하고 작동시키기 위한 전기 신호. 예) 메모리 읽기 / 쓰기 신호.

2 — 명령어 하나가 실행되는 과정

앞의 메모리 표(1번지 “더하라”, 2번지 “저장하라”)를 그대로 실행하면 이렇게 돈다.

Fetch 명령어 읽기 제어장치가 "메모리 읽기"
제어신호를 쏨
Decode Register 저장 · 해석 가져온 명령을 Register 에
3·4번지 data 가 필요함을 앎
Execute ALU 연산 3·4번지 data 를 Register 에
120+100 → 220 도 Register 에
Fetch 2번지 명령어 읽기 "저장하라" 를 가져오려고
제어신호를 다시 쏨
Write 메모리에 저장 Register 의 220 을
5번지에 쓴다

시스템 버스로는 이렇게 나간다

CPU                         System Bus                      Memory
 |   (1) 저장할 데이터  --->  [ data bus    ] --->
 |   (2) 저장할 주소    --->  [ address bus ] --->   "5번지 + 쓰기 + 220 ?
 |   (3) 제어 신호      --->  [ control bus ] --->    아, 5번지에 220 을 쓰라는구나"

#2 데이터 표현과 언어

3 — 데이터 표현

2진수 음수 — 2의 보수

모든 0, 1 을 뒤집고 +1 하면 된다.

1011  ->  0100  ->  0101   (= -1011)
0101  ->  1010  ->  1011   (= -0101)

2진수 → 16진수

2진수 4자리 = 16진수 1자리.

   1    A    2    B   (16)
   |    |    |    |
 0001 1010 0010 1011  (2)

접두사 : 0b01110100 / 0x1a3fb066
인코딩

문자를 0101 로 바꾸는 것. 한글은 완성형 vs 조합형 으로 갈린다.

ASCII Code(8bit), Unicode, UTF-8 / UTF-16 등.

4 — 컴파일 vs 인터프리터

고급 언어              컴파일              저급 언어
[ 소스 코드 ]  --[ 컴파일러 ]-->  [ 목적 코드 ]

고급 언어 : Java, Python, ...
저급 언어 : 기계어 00101001 / Assembly 어 mov, push, rbp, ret, pop, ...
컴파일

소스 코드를 쭉 훑어보고 통째로 변환한다.

컴파일 중 오류가 나면 소스 코드 전체가 실행되지 않는다.

인터프리터

인터프리터가 한 줄씩 실행한다. 전체가 변환되기까지 기다릴 필요가 없다.

오류가 나면 오류 발생 전까지의 코드는 실행된 상태다.

#3 명령어 구조와 주소 지정

5 — 명령어 구조

명령어는 연산코드와 오퍼랜드(주소 필드) 로 나뉜다.

구분 뜻 예
연산코드 무엇을 할지 더해라, 빼라, 저장해라
오퍼랜드 무엇을 가지고 / 어디에 120을, 메모리 33번지 값을, 메모리 128번지에
왜 값이 아니라 “메모리 33번지” 라고 쓰나

오퍼랜드 크기가 제한되어 있기 때문이다. 값을 통째로 넣을 공간이 없으니 위치를 적는다.

오퍼랜드 개수별 구조

연산 코드

ret — 오퍼랜드가 없는 경우 (0-주소 명령어)

연산 코드오퍼랜드

pop rbp — 오퍼랜드가 한 개인 경우 (1-주소 명령어)

연산 코드오퍼랜드오퍼랜드

mov eax, 0 — 오퍼랜드가 두 개인 경우 (2-주소 명령어)

연산 코드오퍼랜드오퍼랜드오퍼랜드

오퍼랜드가 세 개인 경우 (3-주소 명령어)

연산코드 종류

MOVE  STORE  LOAD  PUSH  POP
ADD  SUBTRACT  MULTIPLY  DIVIDE  INCREMENT  DECREMENT
AND  OR  NOT  COMPARE
JUMP  CONDITIONAL JUMP  HALT  CALL  RETURN
START IO  TEST IO  ...
유효주소(effective address)

연산에 사용할 data 가 저장된 위치.

6 — 명령어 주소 지정 방식 (addressing modes)

data 가 저장된 위치를 찾는 방법. 곧 유효주소를 찾는 방법이다.

1

즉시 주소 지정

연산 코드 + 연산에 사용할 데이터

data 를 명령어에 직접 넣는다. data 크기는 작지만 가장 빠르다.

메모리 접근 0회
2

직접 주소 지정

연산 코드 + 유효주소
→ 메모리의 그 자리에 data

유효주소를 그대로 저장한다.

메모리 접근 1회
3

간접 주소 지정

연산 코드 + 유효주소의 주소
→ 유효주소 → data

유효주소마저 길 수 있기 때문에 쓴다. 많이 느리다.

메모리 접근 2회
4

레지스터 주소 지정

연산 코드 + 레지스터 이름
→ CPU 안의 Register 에 data

메모리까지 안 간다. memory 접근보다 훨씬 빠르다.

메모리 접근 0회
문서 오기 하나

원문 3번이 immediate addressing mode 로 적혀 있는데, 간접 주소 지정의 영문은 indirect addressing mode 다. 1번과 영문이 겹쳐 있었다.
